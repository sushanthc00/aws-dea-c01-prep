# Task 4.4 — Prepare logs for audit (D4)

## 1. Log sources → destinations (who/what/when)
| Evidence | Source | Store / analyse |
|---|---|---|
| API calls (control plane) | **CloudTrail** management events | S3 trail (+ Athena), CloudWatch Logs, **CloudTrail Lake** |
| Object/item-level data access | CloudTrail **data events** (S3 object ops, Lambda invoke, DynamoDB items) — opt-in ✓ | same |
| Unusual API activity | CloudTrail **Insights** | EventBridge/SNS |
| Application/job logs | **CloudWatch Logs** | Logs Insights, subscription → Firehose/OpenSearch/S3 → Athena |
| Config changes/compliance | **AWS Config** | S3 snapshots, rules, conformance packs |
| S3 access | server access logs, CloudTrail data events | S3 → Athena |
| Network | VPC Flow Logs, Route 53 resolver logs | S3/CloudWatch → Athena |
| DB activity | Redshift audit logs (connection/user/user-activity), RDS/Aurora logs (audit/slow query/error), DynamoDB via CloudTrail | S3/CloudWatch |
| Query activity | Athena query history/CloudTrail, Lake Formation access in CloudTrail | |
| Large-scale cluster logs | EMR log URI → S3; Spark/Hive logs | EMR/Glue Spark, Athena |

## 2. CloudTrail (4.4.1)
- **Event types**: management (default; control-plane such as `CreateJob`, `PutBucketPolicy`, `DisableKey`), **data** (high-volume object-level; must be enabled per trail/data store), **Insights**, network activity ✓ (Lake lists management, data, network activity events), plus Config items, Audit Manager evidence, and non-AWS events in Lake ✓.
- **Trails**: multi-Region, organization trails; deliver to S3 (+ SNS notifications, CloudWatch Logs); **log file integrity validation** (digest files); encrypt with KMS; event history (90 d) ~.
- Real-time alerts: EventBridge rule on CloudTrail API events (e.g., `kms.amazonaws.com` `DisableKey`/`ScheduleKeyDeletion`) → SNS ✓ (mock Q65). Cross-account KMS calls logged in both accounts ✓.

## 3. CloudTrail Lake (4.4.3) ✓ [CloudTrail Lake](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-lake.html)
- **SQL queries on events** (Trino `SELECT` syntax) over **event data stores** — immutable collections of events (converted to **Apache ORC**) selected by advanced event selectors; one event category per store; **organization event data stores** across Regions/accounts; join across stores; saved queries; dashboards (managed, custom ≤10 widgets, highlights); query results kept 7 days and can be saved to S3; natural-language query generator.
- **Retention** ✓: up to **3,653 days (~10 y)** with the one-year-extendable pricing option or **2,557 days (~7 y)** with the seven-year option; pricing = ingestion + storage + **data scanned per query**; optional own KMS key (cannot be removed or changed afterwards).
- **Federate** an event data store to the Glue Data Catalog and query it from **Athena** ✓; cross-account access with resource-based policy ✓; integrations ingest non-AWS activity via `PutAuditEvents`.
- ⚠ **Availability change** ✓: CloudTrail Lake is **not open to new customers starting 2026-05-31**; existing customers continue. The exam guide v1.1 still lists skill 4.4.3 — know the concept; for new accounts the alternative is trails to S3 + Athena. [exam relevance of the change: unknown]
- Lake vs trail+Athena: Lake = managed, no setup of tables, org-wide SQL, retention features, higher per-scan cost; S3 trail + Athena = cheapest storage, DIY partitioning/projection.

## 4. CloudWatch Logs for application logs (4.4.2) ✓ [Logs Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/AnalyzingLogData.html)
Log groups/streams, retention policies (default never expire → set it), KMS encryption, metric filters, subscription filters (to Kinesis/Firehose/Lambda/OpenSearch), export tasks to S3, cross-account/Region log centralisation (monitoring account ✓), data protection policies to detect/mask sensitive data in logs ~, log classes (Standard/Infrequent Access) ~. Glue **continuous logging** and Spark UI logs ✓; Lambda automatically logs to CloudWatch with the execution role's logs permissions.

## 5. Analyse logs with AWS services (4.4.4)
| Need | Service |
|---|---|
| Ad hoc on recent logs, seconds–minutes | **CloudWatch Logs Insights** (Logs Insights QL, OpenSearch PPL, OpenSearch SQL ✓; 100 concurrent QL queries/account; 60-min timeout; results kept 7 d; billed per GB scanned ✓; field indexes cut scan) |
| SQL over archived logs in S3 (CloudTrail, ALB, VPC Flow, S3 access) | **Athena** (partition projection for date-partitioned logs) |
| Near-real-time search, correlation, dashboards, alerting | **OpenSearch Service** (ingest via Firehose/subscription filter/OpenSearch Ingestion) |
| Managed SQL across org events | CloudTrail Lake |
| Dashboards | Managed Grafana, Quick |

## 6. Integrating services for logging at volume (4.4.5)
Large volume pipelines: sources → **Firehose** (buffer/compress/convert to Parquet, partition by date via dynamic partitioning) → **S3** → **Glue/EMR** Spark for parsing/enrichment/aggregation → **Athena/Redshift** for audit queries; or → OpenSearch for search. **EMR** when petabyte-scale/custom parsing (Spark, Hive) of "big data application logs" ✓ (skills 3.3.8, 4.4.5). Use compression, columnar conversion, partitions (`year/month/day/hour`), lifecycle to Glacier for retention, Object Lock for tamper resistance ~.

## 7. Worked scenarios
1. *Who deleted objects from the bucket?* → CloudTrail **S3 data events** (write) ✓.
2. *Immediate alert when a KMS key is disabled* → EventBridge on CloudTrail events → SNS.
3. *Org-wide SQL on events without infrastructure* → **CloudTrail Lake** (existing customers) / trail + Athena.
4. *Low-cost ad hoc SQL on CloudTrail logs in S3* → **Athena table with partition projection**.
5. *50 TB/day raw app logs parsed for audit reports* → **Spark on EMR/Glue** from S3.
6. *Searchable logs in seconds* → CloudWatch Logs → Firehose → **OpenSearch**.

## 8. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| object-level API audit | S3 data events | management events |
| SQL on events, managed | CloudTrail Lake | CloudWatch metrics |
| tamper-evident trail | log file validation | Config |
| long-term cheap log SQL | S3 + Athena | Logs Insights |
| near-real-time search | OpenSearch | Athena |
| huge raw logs parse | EMR / Glue Spark | Lambda |
