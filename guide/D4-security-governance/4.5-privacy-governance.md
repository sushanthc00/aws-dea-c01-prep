# Task 4.5 — Understand data privacy and governance (D4)

## 1. Permissions for data sharing (4.5.1)
| Pattern | When | Mechanism |
|---|---|---|
| **Redshift data sharing** ✓ | share live warehouse data across clusters/workgroups/accounts/Regions without copying; reads and now writes | producer `CREATE DATASHARE` + `GRANT USAGE … TO ACCOUNT/NAMESPACE`; consumer `CREATE DATABASE … FROM DATASHARE`; cross-account needs authorize/associate; transactional consistency ✓ |
| **Lake Formation cross-account** | share catalog tables/columns/rows | grant to account/org, resource links (RAM) |
| **S3 bucket policy / Access Points** | object-level sharing | resource policies, Access Points, presigned URLs (temporary) ~ |
| **SageMaker Catalog subscription** | governed business sharing | publish → subscribe → owner approves → grants provisioned ✓(S) |
| **AWS Data Exchange** | commercial third-party datasets | subscribe/publish; also Redshift datashares can be licensed ✓ |
| **Clean rooms** | joint analysis without exposing raw data | AWS Clean Rooms ~ (not in the guide's list) |
Principle: share the minimum (columns/rows), prefer live shares over copies, log with CloudTrail, encrypt (shared KMS CMK), revoke centrally.

## 2. PII identification (4.5.2) ✓ [Macie](https://docs.aws.amazon.com/macie/latest/user/what-is-macie.html)
- **Macie** = ML + pattern matching to find sensitive data **in Amazon S3 only**; (1) **automated sensitive data discovery** (continuous sampling across the S3 estate) and (2) **discovery jobs** (targeted, one-time or recurring); **managed data identifiers** (PII, financial, credentials; many countries) + **custom data identifiers** (regex + keywords + proximity) + **allow lists**; also an S3 **bucket inventory** with posture checks (public access, sharing, encryption) → **policy findings**; **sensitive data findings** with severity; findings → **EventBridge** and **Security Hub (CSPM)** ✓; multi-account via Organizations delegated admin; 30-day free trial; **does not mask or modify data**.
- Combine with **Lake Formation**: classify, then tag columns with LF-tags (e.g., `pii=true`) and restrict analyst grants to non-PII tag values ✓ (mock Q26). Remediate through EventBridge → Lambda (tag, quarantine, notify).
- Others: **Glue sensitive data detection** (in ETL; detect/mask/hash), **DataBrew**, CloudWatch Logs data protection ~, Comprehend PII ~, Redshift/Aurora not scanned by Macie.

## 3. Preventing backups/replication to disallowed Regions (4.5.3)
- **SCP** denying actions when `aws:RequestedRegion` ∉ approved list (with exemptions for global services) ✓ preventive; **S3 CRR rules** only to approved Regions; **AWS Backup** plans/copy rules limited to approved Regions; snapshot copy, DynamoDB global tables and Aurora Global DB replicas only in approved Regions; KMS multi-Region keys avoided/limited; Config rules + Access Analyzer + CloudTrail to *detect*; Control Tower region deny guardrail ~; S3 Block Public Access; Organizations tag/backup policies ~.
- Detective vs preventive: SCP = prevent (preferred); Config/CloudTrail = detect/alert.

## 4. AWS Config (4.5.4)
Records **resource configuration history** and evaluates **rules** (managed/custom) → compliance; **conformance packs**, aggregators (multi-account/Region), remediation via Systems Manager Automation (e.g., enforce S3 default encryption) ✓ mock Q37, timeline of changes ("viewing configuration changes" ✓ v1.1 wording); Config items can feed CloudTrail Lake ✓. Not for API-call audit (CloudTrail) or PII (Macie).

## 5. Data sovereignty (4.5.5)
Data subject to the laws of the country where it is stored/processed: control **where data lives and who can access it** — Region selection, SCP region guardrails, single-Region KMS keys (and who holds them), restricted replication/backup, in-Region processing (Glue/EMR/Athena in the same Region), network controls (PrivateLink, no internet egress), access controls with LF/IAM, audit evidence (CloudTrail/Config), AWS European Sovereign Cloud (new Region family; Glue 5.1 available there Aug 2026 ✓), Local Zones/Outposts for local residency ~. Combine **residency** (location) + **sovereignty** (jurisdiction/control) + **privacy** (PII handling).

## 6. SageMaker Catalog and projects (4.5.6) (S)
Producers publish assets/data products into the catalog from their **project**; consumers (other projects) **search, request access (subscribe)**; the owner/approver approves; for managed assets (Glue tables under Lake Formation, Redshift tables) the catalog **creates the grants** automatically; access is then exercised inside the consumer **project** through its project role; all actions auditable; supports business glossary & metadata forms; in IAM-based domains custom asset types allowed (2026). Compare with Glue Data Catalog (technical metadata, no subscription workflow) and Lake Formation (enforcement engine underneath).
Decision: "approval workflow + business metadata + cross-team discovery" → SageMaker Catalog; "enforce column/row permissions" → Lake Formation; "who changed config" → Config.

## 7. Governance framework and sharing patterns (4.5.7)
**Framework pillars**: ownership & stewardship (data owners, stewards, domains/data mesh); classification & tagging (sensitivity, PII; LF-tags, glossary); policy & access (least privilege, ABAC, approvals); quality & lineage (DQ rules, lineage, SLAs); lifecycle & retention (S3 lifecycle, TTL, legal hold); security (encryption, key mgmt, network); audit & compliance (CloudTrail, Config, Macie, reports); cost accountability (tags, Budgets).
**Organisational patterns**: *centralised* (one team governs; Lake Formation admin), *federated/data mesh* (domain teams own data products; central guardrails; SageMaker Unified Studio domains/domain units/projects ✓(S)), *hub-and-spoke* (central catalog + account-per-domain, cross-account LF sharing). **Sharing patterns**: live share (Redshift datashare), catalog-mediated subscription, cross-account LF grants, S3 Access Points, replication (CRR for DR only), marketplace (Data Exchange), copy-with-masking for external parties.

## 8. Backup, DR, residency checklist (links to 2.3.6)
AWS Backup (cross-Region/account, vault lock), snapshot sharing with CMKs, restore tests, RPO/RTO tiers; ensure DR Region respects sovereignty.

## 9. Worked scenarios
1. *Find PII in S3 then hide PII columns from analysts in Athena* → **Macie** + **LF-tags** column grants ✓.
2. *Another account must query warehouse tables live* → **Redshift data sharing**.
3. *EU data and its DR copy must stay in EU* → **SCP region deny** + CRR/backup only to EU Regions + Region-scoped KMS ✓ (mock Q43/Q69).
4. *Detect and auto-fix unencrypted buckets* → **Config rule + remediation**.
5. *Consumer project requests asset; owner approves; access provisioned* → **SageMaker Catalog subscription**.
