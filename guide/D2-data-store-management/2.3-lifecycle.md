# Task 2.3 — Manage the lifecycle of data (D2)
Tags: ✓ verified 2026-10-20 (link) · ~ established, not re-fetched. Skills 2.3.1–2.3.6.

## 1. Redshift ↔ S3: load and unload (2.3.1)
**COPY** (S3 → Redshift): parallel across slices; use **many compressed files, ideally a multiple of the slice count**; point at a prefix or **manifest**; IAM role attached to cluster; formats CSV/JSON/Parquet/ORC/Avro; options `COMPUPDATE`, `STATUPDATE`, `MAXERROR`; **auto-copy** (continuous ingestion from S3 prefix ~). A single huge file loads on one slice → slow ✓. INSERT row-by-row is the anti-pattern.
**UNLOAD** (Redshift → S3): parallel by default, `FORMAT PARQUET`, `PARTITION BY (col)`, encryption/KMS, `MAXFILESIZE`, `MANIFEST`. Use for archiving cold data then Spectrum, or feeding the lake.
**Upsert**: stage table → `MERGE` (or delete+insert in a transaction). **Glue/Redshift connector** uses an S3 temp path. **Spectrum** avoids loading cold data at all.
```sql
COPY sales FROM 's3://lake/curated/sales/dt=2026-10-19/' IAM_ROLE 'arn:aws:iam::123456789012:role/RedshiftCopy' FORMAT AS PARQUET;
UNLOAD ('SELECT * FROM sales WHERE sale_date < ''2025-01-01''') TO 's3://lake/archive/sales/'
  IAM_ROLE 'arn:aws:iam::123456789012:role/RedshiftCopy' FORMAT PARQUET PARTITION BY (sale_date);
```

## 2. S3 Lifecycle: transitions and expiration (2.3.2, 2.3.3) ✓ [Lifecycle transitions](https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-transition-general-considerations.html)
- **Waterfall** transitions: Standard → IA / Intelligent-Tiering / One Zone-IA / Glacier IR / Glacier FR / Deep Archive; Standard-IA → INT / ZIA / GIR / GFR / GDA; GIR → GFR / GDA; One Zone-IA → GFR / GDA; **GFR → only Deep Archive**; **Deep Archive is one-way** (restore + copy to change class). Intelligent-Tiering tiers move automatically (30 d / 90 d / 180 d ✓).
- **Objects < 128 KB don't transition by default** (since Sep 2024) — use `ObjectSizeGreaterThan/LessThan` filters to override; you pay a request charge per transition, so tiny objects can cost more than they save.
- **Minimum storage durations** (early transition/deletion → pro-rated charge ✓): IA/One Zone-IA 30 d, Glacier IR 90 d, GFR 90 d, GDA 180 d. A rule can't move an object out of a class before its minimum duration in one step (e.g., GIR 90 d then GDA → at least 94 d if first transition at day 4).
- Glacier FR/GDA add **40 KB metadata per object** (8 KB billed at Standard + 32 KB at Glacier rate) → aggregate small objects before archiving ✓.
- Transitions are **asynchronous**; billing at destination rate starts when the rule is met even if the physical move is later ✓. Rule changes can take up to ~15 min to propagate ✓. Tag filters are re-evaluated at execution ✓.
- **Expiration**: `Expiration` (current versions → delete marker in versioned buckets), `NoncurrentVersionExpiration`/`NoncurrentVersionTransition`, `ExpiredObjectDeleteMarker` cleanup, `AbortIncompleteMultipartUpload`, `NewerNoncurrentVersions` retention count.
- Restore: archived objects need `RestoreObject` (temporary copy billed at Standard; archive still billed) ✓; tiers Expedited/Standard/Bulk ~.
```json
{"Rules":[{"ID":"logs","Status":"Enabled","Filter":{"Prefix":"logs/"},
 "Transitions":[{"Days":30,"StorageClass":"GLACIER_IR"}],"Expiration":{"Days":1825},
 "NoncurrentVersionExpiration":{"NoncurrentDays":30},
 "AbortIncompleteMultipartUpload":{"DaysAfterInitiation":7}}]}
```

## 3. Versioning and TTL (2.3.4)
- **S3 versioning**: keeps all versions; delete creates a **delete marker**; enable with MFA delete ~; required for CRR/SRR; storage cost grows → lifecycle noncurrent expiration; `Object Lock` (WORM, governance/compliance modes, legal hold) for retention mandates ~; versioning can be suspended, not removed.
- **DynamoDB TTL**: set an epoch-seconds attribute; background deletion at no WCU cost; deletion typically within days of expiry (~48 h) ~; expired items may still appear until deleted (filter in queries); deletions appear in Streams (can archive to S3 via Streams/Firehose); not for exact-time deletion.
- Also: Kinesis retention (24 h–365 d ✓), SQS retention (default 4 d, 60 s–14 d ✓), CloudWatch Logs retention, Redshift snapshot retention, Iceberg `expire_snapshots`.

## 4. Deleting data for business/legal requirements (2.3.5)
- Retention/erasure patterns: S3 lifecycle expiration; Object Lock legal hold (the opposite: prevents deletion); DynamoDB TTL; **right-to-erasure** in lakes: Iceberg/Hudi/Delta row-level `DELETE` then **expire snapshots/remove orphan files** (otherwise old snapshots still hold the data) ✓ (D2 topic-set Q32); for plain Parquet rewrite affected partitions; also remove from backups/replicas/caches/derived tables (and embeddings in vector stores).
- Find the data: Macie (S3 PII discovery), Glue sensitive data detection, catalog tags/LF-tags, lineage.
- Audit: CloudTrail data events, S3 Inventory ~, Config.

## 5. Resiliency and availability (2.3.6)
| Store | Features |
|---|---|
| S3 | 11 9's durability, ≥3 AZ (except One Zone classes ✓); versioning; **CRR/SRR** (async, needs versioning; replicate to One Zone-IA to save; replication time control ~); Object Lock; Multi-Region Access Points ~ |
| DynamoDB | multi-AZ by default; **PITR (up to 35 d ~)**, on-demand backups, **global tables** (MREC/MRSC ✓ quotas), AWS Backup |
| Redshift | automated + manual snapshots, **cross-Region snapshot copy** (encrypted needs KMS **snapshot copy grant** in destination), RA3 managed storage, Multi-AZ RA3 ~, restore to new cluster |
| RDS/Aurora | Multi-AZ, read replicas, automated backups + PITR, snapshots (copy/share cross-Region/account; encrypted need shared CMK), **Aurora Global Database**, RDS Proxy |
| Kinesis/MSK | replicated across 3 AZs ~; retention is your replay buffer; MSK Replicator for cross-cluster/Region ✓ |
| EBS/EFS | snapshots / multi-AZ + AWS Backup |
| Org-wide | **AWS Backup**: policies, cross-Region and cross-account copy, **Vault Lock**, supports S3, DynamoDB, RDS/Aurora, Redshift, EFS… ~ |
DR strategies by RPO/RTO: backup & restore → pilot light → warm standby → multi-site active-active. Residency constraint → restrict copies to approved Regions (SCP, replication rules, backup plans) (4.5.3).

## 6. Worked scenarios
1. *Audit logs: hot 30 days, quarterly access (ms), keep 5 y, then delete* → lifecycle Standard → **GLACIER_IR** at 30 d, expire at 1,825 d ✓.
2. *Versioned bucket growing; old versions needed only 30 d; leftover multipart uploads* → **NoncurrentVersionExpiration 30 d + AbortIncompleteMultipartUpload**.
3. *Session items expire after 24 h, free* → **DynamoDB TTL**.
4. *Encrypted Redshift DR to another Region* → cross-Region snapshot copy + **snapshot copy grant** with destination KMS key.
5. *5-year-old Redshift data, still queryable, cheaper* → **UNLOAD Parquet → S3 + Spectrum**.
6. *Erase a customer from Iceberg lake* → **DELETE + expire snapshots + remove orphans**.

## 7. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| COPY slow, one file | split into multiple files = multiple of slices | bigger nodes |
| archive old Redshift data but query it | UNLOAD + Spectrum | DELETE + VACUUM |
| expire noncurrent versions | lifecycle NoncurrentVersionExpiration | disable versioning (impossible) |
| auto-expire items for free | DynamoDB TTL | scheduled Lambda scan |
| DR copy of S3 in another Region | CRR (+ versioning) | Transfer Acceleration |
| cheapest archive, hours OK | Deep Archive (180 d) | Glacier IR |
| small files lifecycle | filter / aggregate first | transition everything |
| erasure in Iceberg | delete + expire snapshots | drop metadata file |
