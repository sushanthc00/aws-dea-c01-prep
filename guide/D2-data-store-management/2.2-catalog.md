# Task 2.2 — Understand data cataloging systems (D2)
Tags: ✓ verified 2026-10-20 · ~ established, not re-fetched. Skills 2.2.1–2.2.6.

## 1. Two kinds of catalog (know the difference)
| | Technical catalog | Business catalog |
|---|---|---|
| Service | **AWS Glue Data Catalog** (Hive-metastore-compatible), Apache Hive metastore | **Amazon SageMaker Catalog** (in SageMaker Unified Studio; built on DataZone) |
| Holds | databases, tables, columns/types, partitions, connections, schema versions | business glossary, metadata forms, data products/assets, ownership, subscriptions/approvals, lineage |
| Consumers | Athena, Redshift Spectrum, EMR, Glue, Lake Formation, Quick | analysts/data consumers across projects |
| Skills | 2.2.1–2.2.5 | 2.2.6 (NEW v1.1), 2.4.4, 4.5.6 |

## 2. Glue Data Catalog (2.2.1, 2.2.2)
- One catalog per account/Region (cross-account via Lake Formation/RAM resource links); tables point to data in S3 (also JDBC, Kinesis, Kafka schemas); **Hive-compatible** so EMR/Hive/Spark/Presto can use it as external metastore ✓ (Glue job option "Use Glue Data Catalog as the Hive metastore", EMR setting).
- **Consume data from source via catalog (2.2.1)**: Athena `SELECT` on a catalog table; Glue `create_dynamic_frame.from_catalog`; Redshift Spectrum external schema `FROM DATA CATALOG`; EMR Spark `spark.sql` with Glue metastore; Quick datasets. Catalog = schema + location + format (SerDe) + partitions.
- Tables created by: crawlers, Athena/Hive DDL, Glue ETL (`enableUpdateCatalog`; not with LF cell-level filters ✓), console/API/CloudFormation, S3 Tables integration ✓, zero-ETL.
- **Encryption & access**: catalog encryption (KMS), resource policy for cross-account, Lake Formation permissions for fine-grained access.

## 3. Crawlers (2.2.3) — schema discovery
- Crawl S3/JDBC/DynamoDB/etc.; **classifiers** (built-in CSV/JSON/Parquet/Avro/ORC…, custom grok/JSON/XML/CSV); infer schema; create/update **tables and partitions**; one table per consistent prefix; **schema change policy**: update table definition vs **log only**; deletion behaviour (delete from catalog / mark deprecated / ignore).
- Run: on demand, scheduled, or event-driven (S3 events ~); **incremental crawl** (only new folders) ~; sample size options; exclusion patterns; JDBC via connection.
- Typical issues: mixed schemas under one prefix → separate prefixes/exclusions; crawler slow on huge prefixes → incremental/targeted crawl or **partition projection**; type drift → custom classifier or manual DDL.
- Crawler vs manual DDL: DDL is deterministic and free; crawler convenient for unknown/evolving schemas.

## 4. Partitions (2.2.4)
Options to keep the catalog in sync with S3 layouts like `dt=YYYY-MM-DD/`:
| Method | When | Cost/limits |
|---|---|---|
| Crawler | unknown layouts | slow/costly at scale |
| `MSCK REPAIR TABLE` | many Hive-style prefixes added | scans all prefixes |
| `ALTER TABLE ADD PARTITION` (Lambda on S3 event / ETL job) | known partition added | precise, cheap |
| **Partition projection** (Athena table properties) | predictable patterns (date/int/enum) | no catalog partitions, fastest planning; Athena-specific |
| **Glue partition indexes** ~ | millions of catalog partitions | speeds partition lookups |
| ETL `enableUpdateCatalog` + `partitionKeys` | writer adds partitions | |
Limits ✓: Athena can read tables with 10 M partitions but **not more than 1 M in one scan**. Over-partitioning → small files, slow planning; design partitions on filter columns with moderate cardinality.

## 5. Connections (2.2.5)
Glue **connections** store JDBC/ODBC/Kafka/Snowflake/MongoDB/etc. connection properties (secret in Secrets Manager ✓ reference), network config (VPC, subnet, security groups). Crawlers and jobs use them. On-prem DB over VPN/Direct Connect → connection in a VPC subnet with route to it; SG must allow traffic (self-referencing SG for Glue ENIs ~); S3 gateway endpoint/NAT for S3 access.

## 6. Business data catalogs (2.2.6 — NEW) ✓ secondary-verified [UNVERIFIED details in open-questions]
**Amazon SageMaker Catalog** (successor of the DataZone catalog; V2 domains open in SageMaker Unified Studio): 
- Concepts: **domain** (top boundary) → **domain units** (org groups) → **projects** (team workspace with members/roles, compute, assets); **assets/data products** are *published* with business metadata (glossary terms, metadata forms); consumers **search and subscribe**; the owner **approves**; for *managed* assets (Glue/Lake Formation or Redshift) the catalog **provisions grants** automatically; supports custom asset types (e.g., dashboards, PDFs) in IAM-based domains (2026).
- Identity: IAM Identity Center–based or IAM-based domains.
- **Lineage** (OpenLineage-compatible ~) shows upstream/downstream datasets and jobs (skill 2.4.4).
- Contrast: Glue Data Catalog answers "what is the schema and where is it"; SageMaker Catalog answers "who owns it, what does it mean, how do I get access".
Distractor logic: CloudTrail/Config are not catalogs; Glue crawlers populate technical metadata only; Macie classifies S3 data but isn't a business catalog.

## 7. Worked scenarios
1. *New daily partitions invisible in Athena until the crawler runs; pattern predictable* → **partition projection**.
2. *Crawler changed production columns and broke queries* → crawler policy **Log**, review and apply DDL manually.
3. *EMR and Athena must share table definitions* → EMR uses **Glue Data Catalog** as Hive metastore.
4. *Business glossary + subscription approval + lineage across teams* → **SageMaker Catalog**.
5. *Millions of partitions, slow Athena planning* → **partition indexes** or projection.

## 8. Snippets (untested)
```sql
-- Athena partition projection
CREATE EXTERNAL TABLE events (id string, payload string)
PARTITIONED BY (dt string)
STORED AS PARQUET LOCATION 's3://lake/events/'
TBLPROPERTIES ('projection.enabled'='true','projection.dt.type'='date',
  'projection.dt.range'='2025-01-01,NOW','projection.dt.format'='yyyy-MM-dd',
  'storage.location.template'='s3://lake/events/dt=${dt}/');
```
```bash
aws glue create-crawler --name crawl-orders --role GlueCrawlerRole --database-name raw \
  --targets '{"S3Targets":[{"Path":"s3://lake/raw/orders/"}]}' \
  --schema-change-policy '{"UpdateBehavior":"LOG","DeleteBehavior":"LOG"}' \
  --recrawl-policy '{"RecrawlBehavior":"CRAWL_NEW_FOLDERS_ONLY"}'
```

## 9. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| shared metastore for EMR/Athena | Glue Data Catalog | separate Hive metastore |
| predictable date partitions, avoid crawler | partition projection | MSCK every hour |
| review schema changes | crawler Log policy | update table automatically |
| business glossary, subscriptions, lineage | SageMaker Catalog | Glue Data Catalog |
| cross-account tables | Lake Formation share + resource link | copy data |
| JDBC source cataloging | Glue connection + crawler | S3 event |
