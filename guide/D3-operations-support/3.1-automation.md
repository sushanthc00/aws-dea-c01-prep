## 2. Troubleshoot Amazon managed workflows (3.1.2)
| Symptom | Where to look | Typical cause / fix |
|---|---|---|
| **MWAA** DAG not listed | Scheduler / DAG processing logs (CloudWatch) | import/syntax error; wrong `dags/` path; DAG file parse timeout |
| MWAA plugin/requirements fail | Worker/scheduler logs; env status "update failed" | pip needs internet → NAT or VPC endpoints/private repo; version constraints |
| MWAA tasks queued, not running | metrics (queued tasks), worker count | environment class too small; raise max workers; `celery.worker_autoscale`; pool slots |
| MWAA task fails AccessDenied | task log | execution role lacks Glue/S3/KMS permission |
| **Step Functions** execution failed | console graph + execution history/CloudWatch Logs | task error in a state; `States.TaskFailed`, `States.Timeout`; Retry/Catch missing; IAM role for state machine; payload > 256 KiB ✓ |
| SFN history limit | `ExecutionFailed` – history > 25,000 events ✓ | Distributed Map / child executions |
| SFN throttled | `ExecutionThrottled` metric | state-transition / StartExecution quota ✓ |
| **Glue workflow** stuck | workflow run graph | upstream crawler failed; trigger condition not met |
| **EventBridge** target not invoked | rule metrics (`FailedInvocations`), DLQ | target permission/resource policy; pattern mismatch |
Always: CloudWatch Logs + metrics, enable logging on state machines, set alarms (SFN `ExecutionsFailed`, `ExecutionsTimedOut`), EventBridge rule on status change → SNS.

## 7. Query data with Athena (3.1.7)
✓ [Athena capacity](https://docs.aws.amazon.com/athena/latest/ug/capacity-management.html): **capacity reservations** = dedicated serverless DPUs (1 DPU ≈ 4 vCPU/16 GB); min **4 DPUs**; reservation creation can take up to 30 min; queries on reserved capacity **don't count toward DML/DDL quotas**; queued up to **10 hours**; up to 20 workgroups per reservation, 100 reservations / 1,000 DPUs per account/Region; DML uses 4–124 DPUs per query (DDL 4); Spark-enabled workgroups not supported. Per-query billing (per TB scanned) and reservations can coexist. Query string ≤ 262,144 bytes; ≤ 1 M partitions scanned ✓.
Cost/limit control via **workgroups** ~: per-query data-scanned cutoff, workgroup-wide periodic limit with SNS alarm, enforced result location + encryption, CloudWatch metrics, tags for cost allocation, engine version pinning.
Tune: Parquet/ORC, partitioning/projection, compression, CTAS compaction, `LIMIT`, column selection, avoid many small files, result reuse for repeated queries.

## 8. Lambda to automate processing (3.1.8)
Triggers: S3 events, SQS (set max concurrency), Kinesis/DynamoDB Streams (ParallelizationFactor ✓), EventBridge/Scheduler, API Gateway, SNS, Firehose transform. Patterns: validate-and-quarantine uploads, start Glue/Step Functions, enrich/notify, tag/move files, trigger crawlers. Constraints ✓: 15 min, 6 MB sync payload, 10,240 MB, concurrency 1,000; make handlers idempotent; use DLQ/on-failure destination.

## 9. Manage events and schedulers (3.1.9)
EventBridge **rules** (event patterns, cron/rate in UTC ~), **Scheduler** ✓ (time zones ~, one-time, flexible windows, retries, DLQ-like retention, universal targets), **Pipes** (source → filter → enrich → target), **Archive/replay**, API destinations, event buses (custom/partner/cross-account). Monitor with `Invocations`, `FailedInvocations`, DLQ; least-privilege target roles.

## 10. Worked scenarios
1. *New Airflow DAG file isn't visible* → DAG-processing logs for import errors + check `dags/` path.
2. *Standard workflow with 60,000-item inline Map fails at 25,000 events* → **Distributed Map** ✓.
3. *Athena DML queue exceptions during business hours, predictable workload* → **capacity reservation** + workgroup assignment ✓.
4. *Every upload validated, bad files quarantined* → S3 event → Lambda → move to `quarantine/`.
5. *Data engineers + scientists need a governed shared workspace* → SageMaker Unified Studio project.

## 11. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| DAG missing in MWAA | DAG processing log | VPC route tables |
| more than 1,000 S3 keys | paginator | MaxKeys > 1000 |
| predictable heavy Athena load | capacity reservation | bigger workgroup |
| cap per-query Athena cost | workgroup per-query data limit | query timeout |
| time-zone-aware schedule | EventBridge Scheduler | rule cron |
| no-code reusable cleaning | DataBrew recipe | Lambda |
| API abuse by few clients | API Gateway throttling + usage plans | more Lambda memory |
