## 2. Verify and clean data (3.2.2)
- **Lambda** (light validation/quarantine), **Athena** (profiling SQL: duplicates `GROUP BY … HAVING COUNT(*)>1`, nulls `COUNT_IF(col IS NULL)`, ranges, `approx_distinct`), **Quick** (visual checks), **Jupyter / Athena Spark notebooks / SageMaker Unified Studio**, **SageMaker Data Wrangler** (visual prep), **DataBrew** (recipes), Glue Data Quality (see 3.4).
- Typical cleaning: deduplicate (`ROW_NUMBER() OVER (PARTITION BY key ORDER BY ts DESC)=1`), standardise types/dates, trim/case, handle nulls (impute/drop/flag), outlier rules, reference-data lookups, PII masking.

## 3. SQL in Redshift and Athena (3.2.3 — wording changed in v1.1)
- Both: ANSI-ish SQL, CTEs, window functions, views. **Athena** (Trino/Presto-based): views stored in the Glue Data Catalog; CTAS; `UNNEST` arrays; `TABLESAMPLE` ~; Iceberg DML ~. **Redshift** (PostgreSQL-derived): views, **late-binding views** (reference external tables), **materialized views**, SUPER/PartiQL with array functions (new Mar 2026 ✓), stored procedures, `MERGE`.
- Views vs MV vs CTAS: view = stored query (no data); MV = stored result (refresh); CTAS = materialised table (static).
```sql
-- view (Athena or Redshift)
CREATE OR REPLACE VIEW active_customers AS SELECT * FROM customers WHERE status = 'ACTIVE';
```

## 4. Athena notebooks with Apache Spark (3.2.4)
Serverless interactive PySpark/Spark SQL on S3 and the Glue Data Catalog; no cluster to manage; sessions with DPUs; good for exploration, ad hoc transformations, charting; **not supported on capacity reservations** (Spark workgroups excluded ✓). Alternative: EMR Studio, SageMaker Unified Studio notebooks, Glue interactive sessions.

## 5. Provisioned vs serverless trade-offs (3.2.5)
| Dimension | Serverless (Athena, Glue, EMR Serverless, Redshift Serverless, Lambda, Aurora Serverless v2, DynamoDB on-demand) | Provisioned (Redshift RA3, EMR on EC2, Athena capacity reservation, DynamoDB provisioned, Aurora/RDS) |
|---|---|---|
| Ops | none/low | capacity planning, patching windows |
| Cost | pay per use, cheap for spiky/idle; higher unit price at steady 24/7 | cheaper at predictable high utilisation; reservations/Savings Plans (Redshift Serverless 3-yr up to 45 % ✓) |
| Performance | scales automatically; cold-start/queueing variance | predictable, tunable, dedicated |
| Control | limited tuning | full (instance types, WLM, networking) |
| Quotas | account concurrency (Athena DML queue ✓) | reserved DPUs/nodes |
Hybrid example ✓: Athena on-demand for ad hoc + **capacity reservation** for predictable critical workgroups (does not consume DML quota; queue ≤ 10 h; min 4 DPUs).
Rules: unpredictable/dev/test → serverless; steady heavy → provisioned + reservations; peaks over steady base → provisioned + concurrency scaling.

## 6. Aggregation, rolling average, grouping, pivoting (3.2.6)
```sql
-- grouping and subtotals
SELECT region, product, SUM(amount) FROM sales GROUP BY ROLLUP (region, product);
-- 7-day rolling average per store
SELECT store, day, AVG(daily_sales) OVER (PARTITION BY store ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS rolling7 FROM store_sales;
-- running total / rank / lag
SELECT *, SUM(x) OVER (PARTITION BY k ORDER BY d) AS running, RANK() OVER (PARTITION BY k ORDER BY x DESC) AS rnk, LAG(x) OVER (PARTITION BY k ORDER BY d) AS prev FROM t;
-- pivot via conditional aggregation (portable)
SELECT store, SUM(CASE WHEN q = 'Q1' THEN amt END) AS q1, SUM(CASE WHEN q = 'Q2' THEN amt END) AS q2 FROM s GROUP BY store;
-- percentiles / approximations
SELECT approx_percentile(latency_ms, 0.95) FROM requests;   -- Athena
```
Terms: **aggregation** (SUM/COUNT/AVG over groups), **grouping sets/ROLLUP/CUBE**, **window frame** (`ROWS` vs `RANGE`, preceding/following), **rolling average** (fixed-size window), **pivot** (rows → columns; Redshift has `PIVOT`/`UNPIVOT`; Athena uses conditional aggregation or `map_agg`), **time bucketing** (`date_trunc`).

## 7. Worked scenarios
1. *Dashboard slow/expensive; data updates daily* → Quick **SPICE** import + daily refresh.
2. *Rolling 7-day average per store in Athena* → window frame `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`.
3. *Data scientist wants interactive PySpark on S3, no clusters* → **Athena Spark notebook**.
4. *Dev team with intermittent Redshift queries* → **Redshift Serverless**.
5. *Per-salesperson regional rows in dashboards* → **row-level security**.

## 8. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| fast dashboard, daily data | SPICE | direct query to Athena |
| per-user row filtering | RLS permissions dataset | separate dashboards |
| rolling average | window frame ROWS … 6 PRECEDING | GROUP BY |
| find duplicates | GROUP BY … HAVING COUNT>1 | SELECT DISTINCT |
| unpredictable/idle workload | serverless | provisioned 24/7 |
| steady heavy workload | provisioned + reservation | on-demand |
| PySpark without cluster | Athena notebooks | EMR cluster |
