## 1. Observability toolbox (which tool answers which question)
| Question | Tool |
|---|---|
| Is it healthy / how much / how fast? | **CloudWatch metrics** + alarms + dashboards (Glue job metrics, Kinesis `IteratorAge`, Redshift `PercentageDiskSpaceUsed`, SQS depth, Lambda throttles) |
| What did the app print? | **CloudWatch Logs** (log groups, retention, metric filters, subscription filters) |
| Who called which API? | **CloudTrail** (management events default; **data events** opt-in; **CloudTrail Lake** SQL; Insights for anomalies) |
| What changed in configuration / is it compliant? | **AWS Config** (rules, timeline, conformance packs) |

| Workflow state | Step Functions execution history (90 d ✓), MWAA task logs, Glue workflow graph |
| Event → action | **EventBridge** rules (Glue/EMR/DMS/SFN/Redshift state changes) → SNS/Lambda/SQS |
| Cost | Cost Explorer, Budgets (in scope ✓), cost allocation tags |

## 2. Logging and monitoring for audit and traceability (3.3.2, 3.3.7)
- **CloudWatch Logs**: structured JSON logs; retention policy; encryption with KMS; metric filters (turn "ERROR" lines into metrics); subscription filters → Kinesis/Firehose/Lambda/OpenSearch; export to S3; **log classes** (Standard vs Infrequent Access ~); cross-account observability ✓ (monitoring account can query source accounts).
- Enable service logs: Glue **continuous logging** + Spark UI ✓, EMR log URI, Redshift **audit logging** (connection, user, user-activity logs to S3/CloudWatch), S3 server access logs/CloudTrail data events, VPC Flow Logs, Lambda logs, API Gateway access logs, Step Functions logging, MWAA component logs, Athena workgroup metrics.
- Traceability: correlation IDs in logs, lineage (SageMaker Catalog), CloudTrail for control plane, immutable log storage (S3 Object Lock ~), log file integrity validation (CloudTrail).

## 3. Extract logs for audits (3.3.1)
Methods: CloudWatch Logs **export task** to S3; **subscription filter → Firehose → S3** (continuous); CloudTrail trail to S3 (+ **Lake** event data store for SQL); S3 server access logs; Config snapshots to S3; Athena over logs (CloudTrail table with partition projection); Logs Insights for ad hoc.

## 4. Alerts (3.3.3)
CloudWatch alarm (static or anomaly detection ~) → **SNS** (email/SMS/HTTP/Lambda) → on-call; composite alarms; EventBridge rules on failure events → SNS; Step Functions Catch → SNS publish; Glue job **delay notification threshold** ✓; DMS event subscriptions; Redshift event notifications; budget alerts. SQS DLQ depth alarm for poison messages.

## 5. Troubleshoot performance (3.3.4) — symptom → cause → fix
| Service | Symptom | Cause / fix |
|---|---|---|
| Kinesis | `WriteProvisionedThroughputExceeded` | hot shard/too few shards → better key, more shards/on-demand, batch (PutRecords ≤500 ✓), KPL, backoff |
| Kinesis | rising `GetRecords.IteratorAgeMilliseconds` | slow consumer → ParallelizationFactor ≤10 ✓, EFO, more shards, faster code |
| Lambda | throttles / 429 | concurrency 1,000 ✓ default → reserved/provisioned, quota, SQS buffer |
| Lambda | timeout | 15 min ✓ → Glue/Fargate; raise memory (CPU) |
| S3 | 503 Slow Down | > 3,500/5,500 req/s/prefix ✓ → prefixes, fewer small files, backoff |
| Glue | OOM / skew | salting, repartition, larger/R.* workers ✓, AQE |
| Glue | slow listing | small files → `groupFiles`, compaction |
| Glue | reprocessing | bookmarks off / `job.commit()` missing |
| Redshift | queue waits | automatic WLM, concurrency scaling, SQA, query priorities |
| Redshift | slow joins | wrong DIST key (DS_BCAST/DS_DIST), stale stats, no sort key |
| Redshift | locks | `STV_LOCKS`/`SVV_TRANSACTIONS`, `PG_TERMINATE_BACKEND` |
| Redshift | disk full | skew, large temp, resize/RA3, vacuum, drop unused |
| Athena | slow/expensive | Parquet + partition + compaction; `TooManyRequestsException` → capacity reservation ✓ |
| EMR | job slow / Spot loss | instance fleets, task-node Spot only, managed scaling, YARN memory config |
| DynamoDB | throttling | on-demand/auto scaling, key design, adaptive capacity |
| RDS | CPU/connections | RDS Proxy, replicas, Performance Insights ~ |
| MSK | broker CPU/disk, consumer lag | scale brokers/storage, partitions ≥ consumers, `ConsumerLag` metrics ~ |
| OpenSearch | red/yellow cluster, JVM pressure | shards sizing, replicas, storage/instance scale, UltraWarm/cold ~ |

## 6. CloudTrail (3.3.5) — also D4 4.4
Management events (control plane: CreateJob, PutBucketPolicy, DisableKey) recorded by default (90-day Event history, free) ~; **data events** (S3 object-level `GetObject/PutObject/DeleteObject`, Lambda invoke, DynamoDB item ops) are **opt-in** — answer for "who deleted this object". **Insights** detect unusual API volume. **Trails** → S3 (+CloudWatch Logs, SNS); org trails; log file validation (digest). **CloudTrail Lake**: managed event data store, SQL queries, org-wide. Use EventBridge rules on CloudTrail events for real-time alerts (e.g., `DisableKey`, `ScheduleKeyDeletion`).

## 7. Troubleshoot and maintain pipelines — Glue and EMR (3.3.6)
- **Glue**: job run status/error (CloudWatch error log group), continuous logging, job metrics (`glue.driver.jvm.heap.usage`, shuffle, DPU use) ✓, **Spark UI** needs enabled + logs path ✓, retries 0–10 ✓, timeout ✓, `--additional-python-modules` for missing libs, VPC connection (SG self-reference, NAT/endpoints), AccessDenied on S3/KMS/catalog → role, **max concurrency 1** ✓ causing "concurrent runs exceeded" → raise or queue.
- **EMR**: cluster/step state, `stderr/stdout/syslog` + YARN container logs in log URI S3 bucket ✓ (enable *before* failure), Spot interruptions, bootstrap failures, memory (`spark.executor.memory`, overhead), HDFS capacity (core nodes), security group/subnet issues, EMR Serverless job logs, release support windows ✓ (5.36 and 6.6–6.15 extended through 2027-06-30; 7.0–7.10 through 2027-08-31).
- Maintain: patching/upgrade windows, version upgrades (Glue 5.1 default ✓, 6.0 available ✓), dependency pinning, runbooks, alarms on SLAs, DLQs, tests.

## 8. CloudWatch Logs Insights (3.3.7, 3.3.8) ✓ [Logs Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/AnalyzingLogData.html)
- Interactive queries across log groups; **three languages**: Logs Insights QL, **OpenSearch PPL**, **OpenSearch SQL** ✓; limits: **100 concurrent** Insights QL queries per account (15 for PPL/SQL), **60-minute** timeout, results kept **7 days**; billed per **uncompressed GB scanned** ✓; automatic field discovery for Lambda, CloudTrail, VPC, Route 53 logs and JSON logs; **field indexes** reduce scan cost/time; pattern detection; saved queries; cross-account (monitoring account).
```
fields @timestamp, @message
| filter @message like /ERROR/
| stats count(*) as errors by bin(5m)
| sort errors desc
```
- **Analyze logs with**: Logs Insights (recent, ad hoc), **Athena** (S3-resident logs: CloudTrail, ALB, VPC Flow, S3 access, Firehose-delivered CloudWatch logs; cheap, SQL), **OpenSearch Service** (near-real-time search + dashboards, ingest via subscription filter/Firehose), **EMR/Glue Spark** (very large "big data application logs", parsing/enrichment), Managed Grafana for dashboards.
- Pick: seconds-old search + dashboards → OpenSearch; occasional audit SQL on archived logs → Athena; quick troubleshooting on live logs → Logs Insights; 50 TB/day parsing → Spark on EMR/Glue (D4 4.4.5).

## 9. Worked scenarios
1. *Alert when a Kinesis consumer falls behind* → alarm on `GetRecords.IteratorAgeMilliseconds` → SNS.
2. *Email on any Glue job failure/timeout* → EventBridge rule on Glue Job State Change → SNS.
3. *More than 5 ERROR lines in 5 min* → CloudWatch Logs **metric filter** + alarm.
4. *Who deleted objects from the bucket?* → CloudTrail **S3 data events** (write) on that bucket.
5. *EMR step failed and cluster terminated; no logs* → configure **log URI** (S3) at launch.
6. *Searchable app logs in seconds with dashboards* → CloudWatch Logs → Firehose → **OpenSearch**.
