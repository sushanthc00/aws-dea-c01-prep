# Task 1.3 — Orchestrate data pipelines (D1)

## 1. Orchestrator selection (skill 1.3.1)
| | Step Functions | MWAA (Airflow) | Glue workflows | EventBridge (rules/Scheduler/Pipes) | Lambda |
|---|---|---|---|---|---|
| Model | state machine (ASL JSON), visual | Python DAGs on managed Airflow | graph of crawlers/jobs/triggers | event routing, schedules | single function |
| Serverless | ✓ | ✗ (environment class, always-on) | ✓ | ✓ | ✓ |
| Best for | AWS-native workflows, retries/catch, parallel/Map, human approval, SDK integrations (270+ services ✓ via Scheduler UTP; SFN has 200+ ~) | existing Airflow DAGs, rich scheduling/backfill, big operator ecosystem | Glue-only ETL chains | triggering/scheduling; light filtering/enrichment | tiny glue steps |
| Not for | very long polling (cost per transition) / Airflow portability | simple/short chains (idle cost) | non-Glue steps (Athena, Lambda…) | multi-step state, retries across steps | > 15 min ✓ |
| Pricing | per state transition (Standard) / requests+duration (Express) | environment-hours + workers | free (pay for jobs) | per event/invocation | per ms |
Decision: *AWS-native, serverless, least ops* → **Step Functions**. *Existing Airflow* → **MWAA**. *Only Glue* → **Glue workflows**. *Time/event trigger only* → **EventBridge**.

## 2. Step Functions ✓ [SFN quotas](https://docs.aws.amazon.com/step-functions/latest/dg/service-quotas.html)
- **Standard**: up to **1 year** execution, exactly-once workflow semantics ~, history ≤ **25,000 events**/execution (fails past it), history kept **90 days** after close, redrive window 14 days. **Express**: up to **5 minutes**, history unlimited but requires CloudWatch Logs, very high start rate (6,000 start burst), at-least-once (async) / at-most-once (sync) ~, no redrive.
- State input/output ≤ **256 KiB** → pass S3 pointers, not payloads.
- **Map**: inline (concurrency within history) vs **Distributed Map** (child executions; ≤ **10,000** parallel children; ≤ 1,000 open Map Runs) — the fix for large item sets/history limit.
- Resilience: `Retry` (ErrorEquals, IntervalSeconds, BackoffRate, MaxAttempts) then `Catch` → fallback/notify state; timeouts and heartbeats; `Choice` for branching; `Parallel`; `Wait`.
- Integrations: optimized (Lambda, Glue, EMR, ECS, Batch, Athena, SNS, SQS, DynamoDB, Bedrock ~); patterns `Request Response`, **`.sync`** (wait for job completion), **`.waitForTaskToken`** (callback for human approval/long external work — Standard only).
- Pricing note: Standard bills per state transition → polling loops with Wait are costly; prefer `.sync`/callbacks.

## 3. MWAA ✓ [MWAA environment class](https://docs.aws.amazon.com/mwaa/latest/userguide/environment-class.html)
- Managed Apache Airflow; **environment class** sets Fargate worker/scheduler size and metadata DB: mw1.micro (≤25 DAGs, 3 tasks, no autoscaling), small (50/5), medium (250/10), large (1,000/20), xlarge (2,000/40), 2xlarge (4,000/80) — DAG capacity / default concurrent tasks. Schedulers 2–5 (1 for micro); triggerer runs with scheduler for **deferrable** operators/sensors.
- DAGs, plugins, requirements.txt live in an **S3 bucket** (dags/ folder); logs in CloudWatch Logs (scheduler, DAG processing, task, worker, webserver).
- Troubleshooting (3.1.2): DAG missing → DAG processing log import/syntax error or wrong path; package install failure → requirements.txt / VPC egress (NAT/endpoints for pip); task fails → task log + execution role permissions; slow → bigger class / more workers / `celery.worker_autoscale`.
- Use **sensors** (S3KeySensor, deferrable) to wait for files; **operators** for Glue, EMR, Athena, Redshift, Step Functions.
- Cost trap: always-on environment → not for infrequent, simple pipelines.

## 4. Glue workflows and triggers
Triggers: on-demand, scheduled (cron, UTC ~), conditional (job/crawler succeeded/failed), EventBridge event. Workflow = visual graph + shared run properties; supports **crawler → job → job**; no Lambda/Athena nodes. Good for self-contained Glue ETL; otherwise Step Functions.

## 5. EventBridge in orchestration
Rules (event patterns incl. S3, Glue Job State Change, Step Functions status, DMS, Redshift), **Scheduler** (time zones, one-time, flexible windows, retries ✓), **Pipes** (source → filter → enrich → target, e.g., DynamoDB Streams/SQS/Kinesis → Step Functions) ~, archive/replay ~, API destinations (call HTTP APIs with rate limit) ~. Event-driven pattern: **S3 → EventBridge → Step Functions** starts exactly when data arrives.

## 6. Pipelines for performance, availability, scalability, resiliency, fault tolerance (1.3.2)
| Quality | Techniques |
|---|---|
| Performance | parallel branches/Map, right-sized workers, partitioned data, avoid small files |
| Availability | managed multi-AZ services (S3, DynamoDB, Kinesis, SQS, Step Functions), multi-AZ MSK/Redshift RA3, cross-Region copies for DR |
| Scalability | on-demand Kinesis, Lambda concurrency, Glue auto scaling, SQS buffering, EMR managed scaling |
| Resiliency | retry w/ backoff + jitter, DLQs, circuit breakers, checkpoints, bookmarks, idempotent writes, quarantine bad records |
| Fault tolerance | decouple stages (SQS/S3 landing zones), redrive (SFN Standard redrive ✓ 14 d; SQS DLQ redrive), replayable raw data |

## 7. Serverless workflows (1.3.3)
Step Functions + Lambda + EventBridge + SQS/SNS + DynamoDB + S3 + Glue/Athena. Principles: event-driven, stateless functions, state in the workflow/DB, payload pointers, least-privilege per-state IAM, idempotency, observability (CloudWatch, SFN logging, X-Ray out of scope ✓). Human approval = callback task token (Standard). Long waits → Standard (up to 1 y) not Express.

## 8. Notifications (1.3.4)
**SNS** topic (email, SMS, HTTP, Lambda, SQS fan-out, mobile push; filter policies) for alerts and fan-out; **SQS** for durable buffering/decoupling and DLQs (1 MiB messages, retention 4 d default/14 d max, visibility 30 s default/12 h max ✓); EventBridge rules on failure events → SNS; CloudWatch alarms → SNS; Step Functions `Catch` → SNS publish task; Glue job notification/delay thresholds ✓.

## 9. Worked scenarios
1. *Glue job → Athena query → Lambda notify, retries and failure branching, serverless, least ops* → **Step Functions** (`.sync` Glue + Athena, Retry/Catch). Not MWAA (always-on), not Glue workflows (no Athena/Lambda).
2. *Dozens of existing Airflow DAGs, minimal rewrite* → **MWAA**.
3. *Workflow pauses days for a manager's approval* → **Standard workflow + task token** (Express ends at 5 min ✓).
4. *60,000-item Map hits 25,000-event history failure* → **Distributed Map** ✓.
5. *Wait for partner file without holding a worker slot* → MWAA deferrable S3 sensor; or S3 → EventBridge → Step Functions.

## 11. Keyword → answer and traps
| Keyword | Answer | Trap |
|---|---|---|
| serverless, retries, branching, AWS services | Step Functions | MWAA |
| existing Airflow | MWAA | rewrite to SFN |
| human approval / days | Standard + task token | Express |
| high-rate, < 5 min, idempotent | Express | Standard (cost) |
| huge Map / 25,000 events | Distributed Map | raise quota (hard limit) |
| Glue crawler → job chain only | Glue workflow | Step Functions (overkill, still valid) |
| cron with time zone | EventBridge Scheduler | rule cron (UTC) |
| fan-out with per-consumer DLQ | SNS → SQS | single queue |
